## 1. 目标与已确认需求

为 App 开发和测试提供一个本机运行的推送工具：首次配置凭据后，后续打开即可选择设备 token、编辑消息、发送并查看推送服务响应。

用户已确认：

1. 主要测试一个固定 App，支持后续修改应用配置。
2. 默认使用测试环境，同时支持生产环境。
3. 使用 Electron 和 React，支持 Windows 与 macOS。
4. 采用 A 双栏工作台：token 和消息编辑在首页，配置在独立页面。
5. Android 使用 Firebase FCM，导入服务账号 JSON 私钥文件。
6. iOS 直接连接 APNs，同时支持 `.p8` 密钥与 `.p12` 证书。
7. 凭据配置一次后持久保存，token 有历史缓存与下拉选择。
8. 消息编辑同时提供表单和原始 JSON，切换不丢失已有字段。
9. Electron 主进程直接发送请求，凭据和 token 在本机加密保存。
10. 单次向一个设备 token 发送；保留最近 100 条发送记录。
11. 区分服务接受、明确拒绝、连接失败和状态未知，不声称设备已送达。

成功标准：常用配置完成后，一次测试只需要选择 token、修改消息、点击发送；重启、进入设置或切换编辑方式均不造成编辑内容丢失。

## 2. 首版范围

包含：应用与环境配置、凭据导入及替换、token 管理、消息编辑、请求预览、单设备发送、结果详情、最近记录、草稿恢复、双平台运行与打包配置。

首版不包含：账号登录、云端同步、团队共享、远程后台、批量群发、Topic/Condition 发送、定时发送、自动重发、第三方厂商推送、iOS 经 FCM 转发、VoIP/Live Activity 等特殊 APNs 推送类型。

界面默认使用中文。技术字段、原始 JSON 键名和服务返回的错误码保持原文。视觉以浅色背景、白色面板、细边框和蓝色主按钮为主，不增加独立主题系统。

## 3. 首页与设置页

### 3.1 首页：双栏工作台

顶部常驻：工具名称、当前应用、测试/生产环境切换、设置入口。每次启动默认选择测试环境；生产环境采用醒目的文字和颜色标识。

左栏按操作顺序排列：

1. Android / iOS 平台切换。
2. token 搜索下拉框：选择历史、粘贴新值、保存备注、删除记录。
3. 表单 / 原始 JSON 编辑方式切换。
4. 表单中的通知消息、纯自定义数据、通知加自定义数据类型选择。
5. 标题、正文、自定义键值数据；高级参数默认折叠。
6. 发送按钮及当前目标摘要。

右栏展示：最终请求预览、本次发送结果、错误详情与最近发送记录。请求预览显示目标平台、环境和对应的实际消息体；鉴权请求头只展示已脱敏的占位信息。

默认窗口约 1180 × 820，最小约 900 × 680。正常宽度采用双栏；窄窗口时可折叠右栏，允许内容区滚动，发送操作保持容易到达。标题、正文、token 长值不得撑破布局。

空状态明确指出下一步：未配置时提供进入设置的入口；无 token 时允许直接粘贴；无发送记录时显示操作说明。原型里的静态示例不作为正式工具的默认成功记录。

### 3.2 设置页

设置为独立路由，包含应用信息、Android 推送、iOS 推送三个区域。测试与生产各有独立配置。采用显式“保存设置”，校验失败定位到字段；离开未保存设置时提示处理修改。

| 区域 | 字段与行为 |
| --- | --- |
| 应用信息 | 显示名称、Android 包名、iOS Bundle ID；应用身份变化影响 token 命名空间 |
| Android | 为每个环境导入服务账号 JSON，读取并展示 Project ID、服务账号邮箱、文件名和导入状态 |
| iOS `.p8` | Key ID、Team ID、密钥文件，使用对应环境的 Bundle ID |
| iOS `.p12` | 证书文件、可为空的证书密码，使用对应环境的 Bundle ID；展示可解析的有效期信息 |

服务账号 JSON 需要包含有效的项目标识、账号邮箱和私钥；普通 `google-services.json` 不作为发送凭据。`.p12` 导入需校验证书和私钥可用，错误密码或不兼容格式显示具体导入错误。`.p8` 需要可用于相应签名算法的私钥。

测试和生产可以配置相同的凭据，但不会在某个环境缺少凭据时自动借用另一环境的配置。导入检查只证明格式与本地解析通过，不声称服务端鉴权或推送已成功。

从首页进入设置再返回，平台、token 和消息编辑内容保留。修改应用身份或目标项目后，按新身份重新选择 token，不自动沿用旧目标。

## 4. 应用、环境与 token 隔离

应用保留一个当前配置档案，无多应用列表。显示名称修改不改变身份；Android 包名、Firebase Project ID 或 iOS Bundle ID 变化会产生对应的新目标命名空间。

token 命名空间由以下内容确定：

- Android：平台、测试/生产环境、包名、Firebase Project ID。
- iOS：平台、测试/生产环境、Bundle ID。

仅更换同一项目的服务账号或同一应用的 APNs 密钥，不清空有效的 token 历史。旧命名空间的数据保留，恢复原身份后可重新看到；不同身份之间不自动迁移。

token 记录包含本地 ID、完整 token、备注、创建时间和最近使用时间。token 去掉首尾空白；同一命名空间按完整值去重，以最近使用优先排序。下拉菜单和常规记录列表默认显示备注与首尾片段，复制功能可获取完整值。

新 token 可以直接用于发送；填写备注后可显式保存，实际开始发送时也自动记入当前历史。备注可修改，删除历史不会更改已经发生的发送结果。服务报告 token 无效时标记原因，用户决定是否删除。

每次切换平台、环境或应用身份时，加载该命名空间的历史与上次选择；没有可用历史时清空目标。不会把 Android token 自动用于 iOS，也不会跨环境沿用 token。

Android 环境切换选择对应的 Firebase 项目配置，FCM 没有被工具虚构出来的独立测试服务器。iOS 环境切换选择 APNs sandbox 或 production 连接；此选择由用户按实际安装包确定，不依据“测试包”文字推断签名环境。

## 5. 消息编辑与平台适配

### 5.1 编辑状态与 JSON 的权威来源

每个平台独立保存消息草稿，环境切换复用该平台内容，便于比较测试。平台切换不把一套平台 JSON 强行转换为另一套；切回后恢复该平台草稿。

每份草稿保存当前编辑方式、JSON 原始文本、最后一次可解析的平台消息对象及高级参数。表单只修改自己管理的字段，未知字段原样保留；嵌套字段采用路径更新，不使用整个对象重建来覆盖扩展数据。

JSON 尚未合法时，继续保存原始文本但阻止发送和切换回表单，显示错误位置；右栏明确提示预览不可用，不能把旧的合法预览伪装成当前请求。修复后即可继续切换。

JSON 可表达而表单无法表示的结构，保留在原始数据中，对应表单区域提示“由 JSON 管理”，不会用空输入覆盖。修改消息类型会移除与新类型冲突的可见通知字段，但切换前内容仍保留在编辑状态，切回原类型可恢复。

### 5.2 原始 JSON 与发送目标边界

JSON 编辑完整的平台消息内容，目标 token、环境、项目和鉴权由外部选择器控制；界面说明“目标和鉴权由工具补充”，右栏展示拼装后的完整请求。

- FCM：编辑 `message` 内的非目标内容，例如 `notification`、`data`、`android`。编辑器不接受外层 `message` 包装以及 `token`、`topic`、`condition` 等路由字段，发现后明确指出应使用 token 选择器。主进程添加选定 token 和 HTTP v1 外层包装。
- APNs：编辑完整 JSON 请求体，包括 `aps` 及自定义顶层字段；设备 token 位于请求路径，推送环境与请求头通过配置和高级参数确定。

本工具不提供任意 URL 或鉴权请求头编辑，不允许消息内容更改凭据读取位置或发送到其他服务。复制请求预览时不包含私钥、证书密码、OAuth token 或 APNs 鉴权 JWT。

### 5.3 三类消息

| 类型 | Android FCM | iOS APNs |
| --- | --- | --- |
| 通知消息 | `notification` | `aps.alert`，使用 `alert` 推送类型 |
| 纯自定义数据 | 仅 `data`，不生成通知字段 | 界面注明“后台通知”，使用 `aps.content-available = 1` 和自定义顶层字段；`background` 类型、优先级 5 |
| 通知加自定义数据 | `notification` 加 `data` | `aps.alert` 加自定义顶层字段，使用 `alert` 推送类型 |

iOS 后台通知的接收取决于 App 能力和系统调度，工具不把它描述为 Android data 消息的相同行为。FCM 三类消息在 App 前后台的表现也可能不同，不据此承诺 App 回调一定执行。

自定义数据：FCM 的值必须为字符串，非法值明确提示，不能静默转换；APNs 允许 JSON 值，但自定义区域不能覆盖保留的 `aps` 字典。所有字段都使用安全解析与路径更新，禁止从 JSON 原型字段污染配置对象。

高级参数首版：Android 优先级、TTL、通知渠道 ID；iOS 声音、角标、优先级、过期时间、折叠 ID。输入参数与消息类型冲突时指出冲突，不在发送时静默改写。

表单验证涵盖 JSON 语法、基础结构、数据值、必要通知内容、保留字段和平台参数。APNs 普通消息体按 UTF-8 字节检查 4096 字节上限。FCM 展示消息内容序列化后的 UTF-8 字节估算值作为参考，不根据包含目标和包装的 HTTP 总长度阻止发送；最终大小限制由 FCM 响应确认，并保留服务端的具体校验原因。

## 6. 架构和组件职责

选用 Electron 主进程直接连接 APNs / FCM，不额外启动本地 HTTP 服务或远程后台。

| 单元 | 职责 | 主要依赖与接口 |
| --- | --- | --- |
| React 界面 | 首页、设置、编辑状态、请求预览、记录查看 | 只调用 preload 暴露的业务接口 |
| preload 桥接 | 有类型的请求与结果契约 | 不暴露文件系统、任意 IPC 通道或私钥解密能力 |
| 配置服务 | 导入检查、环境配置、身份标识、配置版本 | 凭据仓库与本地存储 |
| 凭据仓库 | 加密保存、读取、替换和删除凭据 | Electron safeStorage、用户数据目录 |
| token 与草稿仓库 | 命名空间隔离、去重、排序、草稿恢复 | 版本化本地存储 |
| 消息模型与校验器 | 表单/JSON 转换、保留扩展字段、构造可预览请求 | 纯逻辑，无网络和私钥依赖 |
| 发送协调器 | 校验发送上下文、冻结请求快照、调用适配器、记录结果 | 配置服务、仓库、推送适配器 |
| FCM 适配器 | 获取短期访问令牌、构造 HTTP v1 请求、解析响应 | 当前环境的服务账号凭据 |
| APNs 适配器 | `.p8` 签名或 `.p12` TLS 鉴权、HTTP/2 连接、解析响应 | 当前环境的 APNs 凭据 |
| 历史与结果模型 | 标准化状态、脱敏、100 条记录裁剪 | 发送协调器与加密存储 |

渲染进程关闭 Node 集成，启用上下文隔离和沙箱；主进程验证 IPC 来源及所有业务入参。只加载应用打包的界面内容，使用限制性 CSP，阻止任意导航与窗口创建。

界面只传递配置引用和消息内容；私钥不通过 IPC 返回界面。导入由主进程打开文件选择框并读取文件，渲染进程仅接收文件名、非机密元信息及校验结果。

异步发送使用唯一请求 ID 和不可变上下文，包括平台、环境、身份、配置版本、token、消息快照和开始时间。发送期间允许继续编辑，但结果固定关联该请求。发送中禁用再次发送、替换当前凭据以及修改当前应用身份，防止并发变更影响鉴权。

## 7. 本地持久化

数据保存在 Electron 的用户数据目录，不写入项目源码目录。普通显示偏好与配置元信息采用版本化 JSON；凭据、token、草稿与历史详情加密保存，避免消息内业务数据和目标 token 明文散落。

使用 Electron safeStorage 的操作系统加密能力：Windows 使用 DPAPI，macOS 使用 Keychain。具体 API 根据实现时锁定的 Electron 版本选择受支持接口，不依赖尚未锁定的未来版本。该机制的保护范围遵循操作系统能力，不承诺防御同一登录用户下的所有进程。

导入 `.p8`、`.p12`、服务账号 JSON 时，保存凭据内容的加密副本；原文件随后被移动或删除不影响已保存配置。证书密码也加密保存，界面不提供明文私钥回显。

加密能力临时不可用时提示解锁或重试，不降级为明文保存，不把已保存配置当成缺失而覆盖。文件采用同目录临时文件加原子替换和版本标识；写入失败显示“未保存”，保留当前编辑内容供重试。

草稿编辑采用短延迟合并写入，切换页面和正常退出时刷新；重启加载最后一次成功写入的版本。加密数据与本机用户身份绑定，首版不提供跨机器导出和迁移。

密钥替换先完成解析、加密和持久化，成功后才切换引用。日志不打印私钥、密码、OAuth token、APNs JWT、完整设备 token 或完整消息正文。

## 8. 发送流程与错误语义

1. 界面提交当前平台、环境、配置版本、目标 token 和消息内容。
2. 主进程再次校验上下文、凭据和平台消息，生成不可变发送快照。
3. 创建本地请求 ID，保存“发送中”记录，右侧绑定该次请求。
4. 适配器使用当前凭据发送，设置有限超时，默认总发送期限 30 秒，包含鉴权耗时。
5. 将明确响应转换为服务接受或服务拒绝；中途断线和超时按是否能确定请求未发送分类。
6. 更新记录和耗时，通知界面；结果区保留发送时的环境、token 摘要和请求内容。

| 状态 | 含义与界面行为 |
| --- | --- |
| 校验未通过 | 尚未发出请求，在对应字段提示，不生成网络发送成功记录 |
| 发送中 | 禁止重复发送，展示开始时间及请求摘要 |
| 服务已接受 | FCM 或 APNs 明确接受请求；显示返回的消息名称或 APNs ID，不显示设备已送达 |
| 服务已拒绝 | 展示中文解释、HTTP 状态、服务错误码及脱敏详情 |
| 未能发送 | 可确认在业务请求发出前失败，例如解析失败、鉴权阶段失败、连接建立失败 |
| 发送状态未知 | 已发出或无法确认是否发出后超时/断线，明确可能已被接受，保留内容供用户决定是否重试 |

任何状态都不自动重发业务推送。HTTP 客户端和 SDK 的默认重试也必须受控，不能在内部隐式重复业务发送。获得短期鉴权 token 的缓存与刷新独立处理，凭据替换后清理相关缓存与旧连接。

历史保留最近 100 条实际发送尝试，以全局开始时间排序；校验错误不挤占记录。可查看详情或载入原平台消息重新编辑，载入不会自动发送，也不会自动切换到生产环境。只有当前命名空间匹配时才可恢复目标 token，否则要求重新选择。

若工具在发送过程中异常退出，重启时将未结束记录标记为“发送状态未知”，不恢复自动发送。持久化历史失败时仍展示已获得的网络结果，并说明记录保存失败，不把服务已接受改写为发送失败。

## 9. 验证与交付

### 9.1 自动化验证

- 消息构造：FCM 三类消息、APNs 通知与后台通知、请求包装、保留字段、参数冲突、UTF-8 大小估算及 APNs 大小限制。
- 编辑切换：表单/JSON 往返不丢扩展字段，非法 JSON 不丢原文且阻止发送；跨平台恢复各自草稿。
- 隔离规则：平台、环境、项目和应用身份变化，token 去重、选择恢复及历史重新编辑边界。
- 凭据和存储：导入格式、错误密码、加密不可用、原文件删除后恢复、保存失败与配置替换原子性。
- 发送状态：明确接受、明确拒绝、发出前失败、发出后超时、并发编辑、配置变更防护、进程中断恢复及无隐式重发。
- IPC：非法来源和不符合契约的参数被拒绝，界面无法读取私钥或指定任意文件与 URL。

网络适配器通过可替换传输层测试成功、失败、超时和断线，不把模拟响应作为真实推送验收证据。加密能力的跨平台行为需在对应系统验证，不能只用替身测试代替。

### 9.2 人工验收

| 场景 | 通过标准 |
| --- | --- |
| 首次使用 | 空状态引导配置；导入对应凭据后可返回首页继续编辑 |
| 重启恢复 | 凭据、token 及草稿保留，每次启动默认测试环境 |
| 修改应用 | 显示名称修改不丢历史；身份改变不自动套用旧 token |
| 页面与编辑方式切换 | 进入设置返回、表单/JSON 切换不丢内容 |
